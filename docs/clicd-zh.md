# 接入 CLICD 云服务器

Paymenter 负责销售、账单、续费和基础操作；重装、终端、快照、网络等操作在 CLICD 原生控制台完成。

## 1. 准备节点

在 CLICD 中下载并启用需要销售的系统镜像，确认公网 IP、NAT 端口池和存储可用。

进入 CLICD 的「API 集成」创建密钥，允许 Paymenter 服务器的出口 IP。所需权限：

```text
container:read container:create container:power container:delete
container:resize container:traffic image:read task:read subuser:create
```

不要把密钥限制为某一台已有实例，否则无法自动开通新实例。

## 2. 添加服务器

Paymenter 后台 → **扩展 → 服务器 → 创建服务器**：

| 项目 | 填写内容 |
| --- | --- |
| 名称 | 例如「香港 CLICD 节点」 |
| 扩展 | Clicd |
| CLICD 节点地址 | `https://node.example.com`，不添加 `/api/v1` |
| CLICD 控制台地址 | 客户实际访问的 CLICD 网址；与节点地址相同则留空 |
| API 密钥 | 上一步创建的密钥 |
| 验证 HTTPS 证书 | 使用有效 HTTPS 证书时保持开启 |

保存后测试连接。API 密钥加密保存在 Paymenter 中，不发送给客户浏览器。

## 3. 创建地区产品

后台 → **产品与服务 → 产品**，选择对应服务器并填写 LXC / KVM、默认镜像 ID、CPU、内存、磁盘、带宽、流量和网络配置，再在计费方案中填写 **CNY 人民币售价**。插件中的服务费用直接读取 Paymenter 账单币种，不另设美元价格。

例如，香港和东京各建一个产品，分别绑定各自节点。客户在产品卡片中选择地区，订单就会开通到该产品绑定的节点。操作系统选项只读取节点中已下载并启用的镜像。

NAT 产品需要填写客户连接使用的 **NAT 公网入口**。不要用节点 API 域名猜测公网 IP。

## 4. 客户和后台怎么使用

- 客户进入「我的服务」，查看配置、IP、流量、运行状态，并执行开机、关机和重启。
- 点击「进入控制台」后，复制页面提供的实例密码，再点击「打开实例控制台」。CLICD 原生页面使用访问码和密码登录；这不是免密登录。
- 后台进入「产品与服务 → 所有服务器」，按节点筛选客户实例，点击「同步实例」更新列表，再点「管理」查看单台实例。

控制台入口使用 CLICD 的实例子账户。只有该账户仅绑定当前实例时才向客户提供登录信息；复用节点已有账户，不把控制台密码写进 Paymenter 服务属性或日志。

运行状态与账单状态分开显示。开关机先返回任务编号，页面查询节点任务结果；“已提交”不表示已经执行成功。

## 5. 开通与续费

保持安装文档中的队列守护进程和每分钟计划任务运行。付款开通、到期暂停、恢复、删除沿用 Paymenter 的服务流程，续费后的到期日期会同步至 CLICD。

暂停服务时同时将节点到期时间设为已到期，避免客户通过原生控制台重新开机；恢复时恢复服务到期日期。节点自身的到期与流量检查也必须正常运行。

开通请求超时后，插件只检查预先记录的实例名称，不自动创建第二台。管理员先在 CLICD 核对：实例已存在可重试开通以完成绑定；确认实例不存在且没有正在执行的开通任务后，才可删除该服务的 `clicd_create_attempt` 属性再重试。

当前 CLICD 资源接口支持 CPU、内存、带宽和 IO 调整，不支持磁盘扩容或切换虚拟化类型。这两种升级会明确报错，请勿将它们作为自动升级套餐销售。

## 已有站点更新

使用本仓库文件更新站点后，在网站目录执行：

```bash
php artisan migrate --force
php artisan optimize:clear
php artisan queue:restart
```

更新包含人民币默认设置的迁移；前端构建资源已随仓库提供，不需要安装 Node.js。不要在已有站点上重新执行 `sh init.sh`。
