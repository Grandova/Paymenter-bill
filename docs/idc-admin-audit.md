# Paymenter IDC 后台审计与改造映射

## 审计范围

审计基于 Paymenter 当前 Laravel、Filament、Livewire 页面和模型，重点覆盖商品、自动化接口、实例、订单、账单、用户余额与续费流程。改造继续复用 Paymenter 的 Server Extension、支付扩展、模型关系、权限和审计机制，不另建插件协议或重写核心生命周期。

当前依赖约束为 Laravel 13、Filament 5、Livewire 4；实现沿用 Resource、Schema、RelationManager 与现有模型/Observer。验证在 Linux PHP 8.3 中执行，不构建 Windows 版本。

ZJMF 3.7.6 的后台菜单和管理逻辑文件受 ionCube 保护，无法从源码可靠核实具体交互。本审计不把文件名推断成已验证的产品行为。Xboard 的可读管理端代码显示，套餐与节点分开管理，列表支持排序和关联用户数，订单支持筛选、排序、分页和人工状态操作。可借鉴其信息集中方式，具体 IDC 生命周期仍以 Paymenter 插件能力为准。

## 现有功能对应关系

| 日常业务 | Paymenter 现有入口 | 当前能力与边界 |
| --- | --- | --- |
| 商品与套餐 | `ProductResource` | 商品、分组、库存、限购、套餐价格、购买选项、升级关系和动态服务器插件参数集中在商品表单；套餐支持多币种及小时、日、周、月、年周期。 |
| 自动化接口 | `ServerResource` | 按 Server Extension 动态生成接口参数，支持列表连接测试；商品动态参数由所选接口生成。不能把不同插件的资源字段写死成统一表单。 |
| 用户订单 | `OrderResource` | 订单列表和用户关系已有管理入口；付款、取消应走现有订单及发票流程，不能只改状态字段。 |
| VPS/主机实例 | `ServerInstanceResource`、`ServiceResource` | 实例列表展示用户、商品、接口、状态、套餐和到期时间；详情通过服务记录和扩展能力处理。通用批量删除已移除，避免绕过扩展终止、付款中保护和库存回补。 |
| 账单与流水 | `InvoiceResource`、`InvoiceTransactionsTable`、余额管理 | 发票、支付流水、调整单和账户余额分开管理；账单金额以分为单位核算，人工财务操作保留权限与审计。 |
| 用户服务台账 | `UserResource` | 用户资料关联服务、账单、余额流水、支付协议和工单，减少按用户跨模块查找。 |
| 营销与返利 | Affiliates 扩展、优惠券 | 返利开关由扩展启用状态控制，可配置全局默认比例和单个邀请人的比例；返利发到账户余额并保存发票级金额快照。 |
| 系统配置 | Settings、Gateway、Extension、审计与计划任务资源 | 保留 Paymenter 原设置模型和扩展机制；需要按运营任务重新分组时优先调整导航，不复制配置存储。 |

## 已落地的导航分组

1. **工作台**：数据概览，保留原有收入、服务和工单统计。
2. **业务管理**：商品管理、商品分组、自动化接口、实例管理、订单管理、服务台账与取消申请、购买配置项。
3. **客户与财务**：用户管理、账单管理、支付流水、工单管理、余额流水、优惠券、邀请返利。
4. **系统管理**：支付接口、插件管理、通知模板、公告、邮件记录、系统设置、角色权限、计划任务、队列失败记录、操作审计、请求及错误日志、API、OAuth、币种、税率和系统更新。

保留原资源地址、模型与权限键。支付流水新增侧边栏直达入口，仍使用账单集群内的原页面；无流水查看权限的管理员看不到入口，直接访问也会拒绝。服务台账保留非服务器商品、取消申请等原有功能，不以实例列表替代全部服务记录。公告与返利菜单仍遵循扩展是否启用的原机制。菜单分组和直达入口在请求时翻译，避免语言切换后出现中英文分组混排。

## 页面交互方案

- 商品使用完整分区表单：基础销售资料、自动化接口及该插件的资源参数、计费周期与多币种价格、购买选项、库存/限购、升级关系。表格保留搜索、状态筛选、排序、复制和安全的批量上下架。
- 接口管理仍以 Extension 为唯一配置来源：新增/编辑时显示插件参数，在列表直接测试连接并展示接口名称、插件类型、关联商品数和启用状态。
- 实例列表面向运维任务：按用户、商品、接口、状态和到期时间检索；详情提供账单与服务台账入口，实例操作只显示插件实现的能力，并记录操作结果。
- 订单和财务列表保持高密度表格，支持筛选、排序和分页；补充人工支付、退款、余额变更等操作时必须保留事务一致性、权限校验和审计记录。
- 简单状态调整使用行内或弹窗操作；会影响远程资源、资金或服务期限的操作使用确认表单并显示影响对象。

## 已验证的试点改进

- 商品保存先读取所选 Server Extension 的动态参数，再在事务内保存商品和插件参数。插件接口异常时不会遗留半成品商品，也不会先修改旧商品资料。
- 商品套餐增加月付、季付、半年付和年付快捷选择；保存时仍写入原计费单位和间隔字段，小时、日、周等自定义周期继续可用，不新增套餐数据库字段。
- 批量上下架使用商品修改权限并逐条校验策略；商品复制要求创建商品权限。原模型审计继续记录上下架变更。
- 自动化接口列表按插件和启用状态筛选，关联商品数可直达原商品列表并带接口筛选条件；继续使用原有接口配置与连接测试方法。
- 实例操作只提供对应扩展实现的能力，终止另校验删除服务权限；插件明确返回失败时不再提示成功或把服务错误地改为暂停、恢复状态。原扩展操作审计继续使用。
- 服务列表不再提供绕过单条服务生命周期的通用批量删除；单条删除仍走现有扩展终止、付款中校验、库存处理和审计路径。
- 管理员账单 API 拒绝编辑或删除已付款、含成功或处理中付款的账单；写入在数据库事务内锁定并复查。启用不可变账单时，API 继续仅允许修改、删除草稿。付款中的取消请求保留原有 422 业务校验响应。
- 客户余额页面按系统分页设置展示完整余额流水，并提供翻页入口，不再只显示最近 20 条。
- 账单当前余额和剩余应付额统一按分计算。
- 支付流水支持账单号/用户/流水号搜索、状态/渠道/日期筛选，并显示退款额与入账时间。金额、手续费排序使用真实数据库字段，预加载账单、币种和用户关系；成功、处理中及已入账/退款流水不能经独立列表或批量删除操作移除。
- 最新商品试点通过 8 项测试、44 个断言；导航与余额页通过 7 项测试、23 个断言；导航、接口与实例回归通过 17 项测试、138 个断言。账单整组回归发现并修正一处 API 返回码兼容问题，相关 API 复测通过 4 项测试、30 个断言。上述测试不等同于真实支付网关或真实实例开通验收。
- 接口筛选和实例失败/权限保护最新回归通过 10 项测试、101 个断言；支付流水筛选、排序和批量删除保护通过 2 项测试、20 个断言。

## 最新界面与查询验收

- 商品创建页已检查 1440×900 桌面和 390×844 手机视口：桌面双列表单，手机单列，标签栏可横向滚动，页面本身无水平溢出。

## 页面加载优化（2026-10-11）

- 首页只加载实际展示的商品分组，不再提前读取全部商品、套餐、价格和币种。
- 商品列表保留展示售价所需的套餐与币种，结算配置项留到原结算页面加载。
- 顶部购物车角标直接统计条目数，不加载商品价格、配置项；仍按条目而非购买数量计数。清空购物车后保留 Livewire 根节点，避免刷新角标报错。
- 后台订单列表一次预加载服务金额，10 条订单的服务读取由 10 次降为 1 次。查询回归同时核对数量和金额，不以减少查询牺牲原行为。
- 商品及分组图片增加浏览器懒加载和异步解码。
- 前端生产资源构建、Blade 预编译通过。Linux 部署的 OPcache、静态资源压缩和缓存配置已补充到安装文档。
- 本机登录页 HTTP 测量：原 Windows 挂载目录首字节约 7.79 秒；同一代码和 SQLite 测试库迁移至 Linux 原生目录、启用 OPcache 后，冷请求约 0.86 秒、连续两次预热请求约 0.24 秒。此为本机开发环境测量，不是生产压测或浏览器完整加载耗时。
- 本地 `18089` 预览已切换到 `/tmp/paymenter-idc-regression-maYXcT` 的验证快照，沿用原预览 SQLite 数据库和登录会话。主源码仍在原项目目录；后续源码修改必须同步快照或重启回源码目录，不能把快照误认为源码。
